Concrete implementation contract for #54–58, before backend changes.

Prototype question: keep comparison, temporary search constraints, group/order and explicit private visits separate from Passport and existing Saved records. In-memory HTML prototype covers comparison cap, group move, visit/undo, owner switch and expired-reference resume. No production writes.

Decision: comparison is ephemeral, owner-scoped and limited to 3 current place projections (entity/token used only for current Save; no notes). Search recovery stores only city/category/reference ID+name/trait choices/budget for 7 days per browser owner; NO results or signed tokens. Resume is deliberate; reference is searched again before a new Twin request. Clear removes the draft and temporary choices; Passport stays unchanged.

Organisation and visits use one additive private document table: user_travel_state(user_id UUID PK FK neon_auth.user ON DELETE CASCADE, revision integer, state JSONB, updated_at). Old collection/collection_item records and notes are untouched. Strict projected payload: up to 20 trip metadata records, 10 groups per trip, 100 placements per trip, 100 declared visits; 60-character group names, 280-character visit reasons. No provider images, signed tokens, coordinates, account IDs or private Saved notes in the document. Atomic compare-and-swap revisions reject conflicts with HTTP 409; no silent last-write replacement. Auth and same-origin checks use the existing account-route wrapper and intended-owner header. Guests use a separate browser document, never implicitly migrated; account failures retain the visible draft with explicit retry/reload. Deletion removes the document; account deletion cascades.

Post-visit feedback is private trip history: Would go again / Not for me plus optional reason, only after explicit visit declaration. It does not hide a place, alter existing preference votes, mark a city visited, or change Passport/ranking. This zero automatic ranking effect is explicit in copy and tested; integration with ranking is deferred rather than inferred.

Notebook extends existing Share trip with deliberate selection, ordered public name/city/address projection, export date and group labels. Standalone downloadable HTML + printable view; no maps/images/notes/tokens/feedback/account data, no offline navigation promise. Existing links/postcards remain. Groups are public ONLY in this deliberate export preview; existing shared link schema remains unchanged.

Migration is additive, idempotent and contains no user-data transformation. The explicit owner instruction to implement all six and publish authorizes this necessary extension after this reviewable proposal. Production migration is applied only after local validation, before publication. Physical devices/native assistive technology and real signed-in/cross-device acceptance remain separate evidence, never inferred from fixtures.
